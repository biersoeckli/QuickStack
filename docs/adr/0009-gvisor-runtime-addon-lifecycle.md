# Keep gVisor as a non-removable runtime Add-on

QuickStack provides gVisor as a trusted Cluster Add-on that can be installed, inspected, and explicitly updated but never removed, because its installation changes node hosts and K3s runtime configuration. Its visible and installed version is the explicit, code-defined gVisor date-based release rather than a wrapper SemVer; its Add-on-owned ConfigMap persists that desired version. Each installation or update uses the official, pinned gVisor Debian repository and completes only when every schedulable node is ready. It provides the optional `gvisor` RuntimeClass beside, rather than in place of, the default runtime class. A privileged DaemonSet coordinates host changes through a cluster-wide Lease, preserving existing K3s templates by managing only a marked gVisor block. A new compatible `amd64` or `arm64` Ubuntu/Debian node changes the Add-on to `updating` while it is brought to the pinned version automatically and serially; an incompatible node or failed rollout changes it to `failed`. An explicit retry only processes unverified or divergent nodes, leaving a failed node cordoned without automatic rollback. Cordon never drains workloads. Readiness is based on static host and Kubernetes checks rather than a test workload, and successful nodes receive QuickStack gVisor labels whose version is the node's actual installed version; later static checks report manual drift without repairing it. The UI requires confirmation before an install or update because host mutations are irreversible and can briefly interrupt a single-server control plane.
