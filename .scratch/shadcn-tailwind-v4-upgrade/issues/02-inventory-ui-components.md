# 02 — UI-Komponenten inventarisieren

**What to build:** Eine schriftliche Inventur aller Dateien im UI-Verzeichnis, die jede als
„upstream-adoptierbar“, „lokal angepasst“ oder „projekteigen“ klassifiziert. Sie ist die Grundlage,
um spätere Registry-Re-Adds gefahrlos zu mergen, ohne lokale Anpassungen zu verlieren.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] Jede UI-Datei ist genau einer Kategorie zugeordnet.
- [ ] Lokal angepasste Upstream-Dateien haben eine kurze Zusammenfassung ihrer Abweichungen.
- [ ] Projekteigene Dateien sind als „nicht überschreiben“ markiert.
- [ ] Ergebnis liegt als Markdown im Feature-Ordner; keine Produktionscode-Änderung.
